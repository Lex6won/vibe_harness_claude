# 하네스 회신 — 변경통지(2026-08-03) 반영 완료

> **참조**: `하네스_변경통지_2026-08-03.md`, 갱신된 `하네스_집행계약.md`(§4-0/§9/§10)
> **작성**: vibe_harness 담당 · 작성일 2026-08-03

## 1. 필수 수정 사항(§2) — 반영 완료

`kev_checked` 필드를 확인하도록 고쳤습니다. `in_kev=False`이고 `kev_checked=False`이면
'악용 없음'이 아니라 '대조 못 함'으로 처리해 모드별로 warn/block합니다
(`_kev_unchecked_row`). `in_kev=True`는 `kev_checked` 값과 무관하게 그대로 절대차단입니다.

## 2. 확인 요청(§6) — §4-0을 어떻게 구현했는지

이전까지는 `source_scope`를 판정 결과에서 못 읽어(그 필드가 없었으므로) 직접/전이
구분을 구현하지 못한 상태였습니다. 이번에 필드가 실제로 붙는 것을 확인했고, `unknown`
차단 판정에서 `source_scope in (lockfile, installed)`이면 ENFORCE에서도 `block` 대신
`warn`으로 낮추도록 반영했습니다(`single`·`manifest`는 그대로 차단). 악성·기관차단·
미존재·KEV는 §3 절대규칙이라 scope와 무관하게 그대로 적용됩니다.

## 3. 함께 반영한 것

- `version_exact=False`인 `vulnerable` 판정은 어떤 모드에서도 `warn`을 넘지 않습니다(경계값
  추정만으로는 차단하지 않음, §3-1).
- `registry_status` 확장분(`rejected`·`item_failed`)을 인식합니다. 다만 이 값들은 개별
  패키지 판정에 반영하지 않고 **담당자 채널로만** 보냅니다(§1 원칙 — 시스템 문제는
  사용자에게 개별 차단처럼 보이면 안 됨).
- **레지스트리 미조회 공백을 찾아 고쳤습니다**: 기존 구현은 단건 설치 확인
  (`gvskb_gate.py check/install`)이 `check_package_impl`을 직접 불러 **gg-trusted-registry를
  전혀 조회하지 않고 있었습니다**(레지스트리 연동은 `audit_manifest` 안에만 있음). 지금은
  단건 확인도 1건짜리 매니페스트로 감싸 `audit_manifest`를 거치도록 바꿔, 실시간 설치
  게이트에서도 기관 승인/차단이 반영됩니다.
- 사용자 화면 문구를 §1 원칙에 맞춰 다시 짰습니다: 통과는 완전히 침묵, 차단·경고는
  한 줄(판정 근거·필드명 없이) + 다음 할 일 하나만 붙습니다. 시스템 문제는 stderr에
  `[관리자용]` 접두사로 분리했습니다.

## 4. 테스트 중 발견한 것 — 코드와 무관, 확인 필요

오프라인 인텔 캐시(2026-07-30 갱신분, 11,582건)에 `fastapi`가 악성으로 등재되어
있습니다(`MAL-2026-4750: "Malicious code in fastapi (PyPI)"`). uvicorn·pydantic·
jinja2·sqlalchemy·psycopg·authlib 등 다른 승인 패키지는 이 캐시에서 깨끗합니다 — fastapi만
단독으로 걸립니다.

`fastapi`는 골든 템플릿(`gg-webapp`)의 핵심 의존성이자 `org-packages.yaml` 승인 목록에
있는 패키지입니다. 이게 사실이면(진짜 공급망 공격이면) 심각한 사안이고, 캐시 데이터
오류라면 정정이 필요합니다 — **어느 쪽인지는 하네스가 판단할 사안이 아니라서 그대로
보고합니다.** `gvskb update-intel`로 캐시를 갱신해 재확인하거나, OSV 원본
(`MAL-2026-4750`)을 직접 대조해 주시기 바랍니다.

## 5. §10(우회 정책) — 아직 3자 합의 대기, 이번엔 손대지 않음

등급별 우회 경로(§10-2)·`not_found` 예외(§10-3)·레지스트리 통보 경로(§10-6)는 레지스트리
쪽 `override` 봉투 필드가 아직 없어 3자 합의가 끝나기 전에 하네스가 먼저 구현하면 다시
뜯어고쳐야 할 가능성이 큽니다. 지금 `gvskb_gate.py`의 예외 코드 기능(21번 회신 때 반영)은
§10보다 단순합니다 — 차단 사유를 구분하지 않고, 절대규칙 4종만 우회 불가로 뒀습니다. 3자
합의가 끝나면 그에 맞춰 다시 반영하겠습니다.
